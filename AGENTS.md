# Spool Studio: notes for coding agents

Local-only Preact + esbuild app for LV cable sizing and drum planning. No backend. The only AI is the optional local-model reader below; no hosted AI service, ever.

## The app is the engineer's Excel sheet
The source of truth is the engineer's step09 cable sizing workbook (kept outside the repository; `public/templates/cable-sizing.xlsx` is a byte-for-byte copy) ("Cable Sizing" sheet plus the Settings, Lists, CableTypes, Cores, Methods, Ratings, Factors and FaultData lookup sheets). The app shows that sheet's columns A–BT: the same 72 columns (sizing A–AO, earth fault loop and CPC AP–BG, short circuit BH–BO, motor starting VD BP–BT), the same headings, the same yellow/blue/grey colour legend, the same narrowing dropdowns and the same formulas. Do not add columns or rename headings without a request.

## Motor starting voltage drop (step09, 2026-11-17, user-requested)
- step09 = step08 plus five columns inserted after BO (scratch XML script; every hidden helper moved five columns right: the step05 helpers to BU–CD, the fault helpers to CE–CU). BP Starter Type (list: DOL, Star-delta, Soft starter, VFD from Lists K:L; blank = no check), BQ Starting Current (× Ib; blank = the starter's multiple on Lists: 6, 2, 3, 1), BR Starting VD (%) = AL + (multiple − 1) × AK, i.e. total VD at From (running) + this cable's VD at the starting current, BS Permissible Starting VD (%) (blank = Settings `Def_StartVD`, Settings C13 = 15), BT Starting VD Check.
- The user picks the starter type; the load-list reader maps a "Starter Type" column (DOL, D.O.L, Star/Delta, VSD, Soft start…; "-" or N/A = blank) and keeps anything else as typed (red, not in list). The tabulated mV/A/m is used at starting (it covers the low starting power factor); the extra starting current in the upstream feeders is not added. The cable size suggestion (AB) does not consider starting VD, as in the workbook.
- BP–BT never held saved inputs, so `sheetLayout` stays 8. `TABLES.starters` and `TABLES.defaults.startVd` come from the workbook.

## Earth fault loop, CPC and short-circuit columns (step08, 2026-11-04, user-requested)
- TN-S and TT only (the user's scope), to SS 638:2018 and IEC 60364. step08 = step05 plus 26 columns inserted after AO (rebuilt from step05 by a scratch XML script): AP earthing system (TN-S/TT, blank = Settings `Def_Earthing`), AQ Ze, AR Ra (TT electrode + PE), AS device, AT Ia, AU RCD IΔn (mA), AV required disconnection time, AW CPC type, AX CPC size, AY CPC resistance, AZ Table 54.2 minimum, BA R1+R2, BB Zs, BC max Zs (TT: max Ra), BD If, BE earth loop check, BF CPC check method, BG CPC check, BH fault level at From, BI breaking capacity, BJ breaking capacity check, BK clearance time, BL let-through I²t, BM fault level at To, BN min size, BO short-circuit check. The step05 helpers sit in BP–BY (insulation in BU); fault helpers are BZ–CP (CO system used, CP IΔn in A). Columns A–AO kept their letters.
- Rules: max = the larger of the overcurrent and RCD limits. TN-S (SS 638 411.4.5L): Zs x Ia ≤ U0 or Zs x IΔn ≤ 50 V, so Cmin x U0 / Ia (`Def_Cmin` = 1, nominal U0 = V/√3 rounded to 10 V for 3-phase) or 50 / IΔn. TT: Ra x IΔn ≤ 50 V (411.5.3L) or Ra x Ia ≤ 50 V (411.5.4L); the check uses Ra when typed, else Zs (411.5.3L Note 2). Required time (Table 41.1): final circuit (In ≤ 32 A and no row's From equals this To) by U0 band, TN-S 0.8/0.4/0.2/0.1 s, TT 0.3/0.2/0.07/0.04 s; else TN-S 5 s (411.3.2.3L), TT 1 s (411.3.2.4L). An earthing system outside the list (e.g. IT) leaves AV and the loop checks blank; case is ignored like Excel's =.
- CPC: type blank = earth core for 5C 3-phase / 3C 1-phase (full size) / 3C+3E, else separate copper conductor; armour and tape need catalogue area and resistance. The CPC passes by selection when ≥ the IEC 60364-5-54 Table 54.2 minimum (k1/k2 for armour), else falls back to the adiabatic check (543.1.2) with t = clearance time or the required time. Short circuit (IEC 60364-4-43:2023 431.5.4): breaking capacity ≥ fault level at From; k²S² ≥ I²t, and an MCB row with no let-through that fails shows "Check let-through" (not a FAIL).
- Ze chains like the VD: typed value, else the row whose To matches this From (its Zs BB; for a TT row only when that row is TT too), else (TN-S only) the Transformer Rating, else Settings `Def_Ze`. A TT row with no typed Ze and no TT feeding row shows "Enter Ze". Fault level chains the same way for both systems (BM, transformer, Settings).
- `faultCells` in `src/engine/sheet.ts` mirrors the formulas; FaultData holds the CPC type table, the Table 41.1 times (TN-S and TT columns) and the earthing list, extracted to `TABLES.fault.cpcTypes`/`disconnection`/`earthing` and `TABLES.defaults.earthing`. `CHECK_COLS` = AG, AN, BE, BG, BJ, BO, BT. Item numbering (A) counts only the original 23 inputs.
- Saved projects carry `sheetLayout: 8`. A project without it holds step06 or step07 fault letters; `Project` preprocess moves them once (`LEGACY_FAULT` in `src/store/schema.ts`). Never reuse a fault column letter for a new meaning without bumping `sheetLayout` and adding a move.
- `tests/fixtures/excel-fault-crosscheck.json` holds 165 generated circuits (the TN-S network, TN-S RCDs, four TT installations with typed Ze, Ra, RCDs and overcurrent devices, TT fed from TN-S and back, lower-case and invalid systems) recalculated and saved in Microsoft Excel on 2026-11-04 (0 errors in the sheet); `tests/sheet.test.ts` must keep matching it. Not modelled: TN-C, TN-C-S and IT, reactance, IEC 60909 c factor and minimum fault current, RCD discrimination, TN-S times for a bonded TT installation, Annex A.3 exemptions.

| | Single cable (tab `single`) | Load list (tab `list`) |
|---|---|---|
| UI | `src/ui/SingleCable.tsx` | `src/ui/LoadList.tsx` |
| Rows | One row (`project.single`) | Many rows (`project.list.rows`) imported from XLSX/CSV, pasted or typed |
| Behaviour | Exactly the workbook. The only "suggestion" is the workbook's own Suggested Cable Size column (AB) | The workbook, plus preliminary suggestions for blank cells (`src/engine/suggest.ts`) |
| Excel | Optional export of the row | Optional export of the whole list |

- Suggestions only fill blanks: protection In (next standard rating ≥ Ib), cable type, cores and method (list-wide defaults the engineer picks), permissible VD, cable size (column AB) and no. of cables. A typed value is never overwritten. Suggested cells render in blue italics; "Accept suggestions" turns them into ordinary values. Exports include suggested values as entered values.
- Cable run length is never suggested.

## Engine rules
- `src/engine/sheet.ts` copies the workbook's row-2 formulas column by column, including blank-cell rules (blank diversity = 1, THD = 0, factors = 1, no. of cables = 1), "Out of range", "None passes", the From/To upstream VD chain (blank From means no total VD) and the red-cell conditional formats. Keep it that way.
- `tests/fixtures/excel-crosscheck.json` holds 260 rows of inputs with the values Microsoft Excel itself calculated. `tests/sheet.test.ts` must keep matching them. If you change a formula, the fix must still match Excel.
- Built-in data: `src/data/sizing-tables.json` and `public/templates/cable-sizing.xlsx` are generated by `node scripts/extract-workbook.mjs <workbook.xlsx>`. Never hand-edit the JSON. There is no catalogue upload or review screen; the workbook's tables are the catalogue.
- Export (`src/export/template.ts`) writes the inputs into the template's sheet XML with JSZip so every formula, dropdown and colour rule stays live; lists longer than 196 rows extend the template. Do not re-save the template through exceljs: it scrambles the OFFSET dropdown validations.

## Load list from schematics (2026-10-30)
- Load list → "From schematic" reads PDF (text layer; OCR for scanned pages), ASCII DXF (TEXT/MTEXT/block ATTRIBs) and PNG/JPG/WebP (OCR). `src/import/schematic-read.ts` reads files in the browser; `src/import/schematic.ts` is the pure, deterministic engine (no AI model); `src/ui/Schematic.tsx` is the review dialog.
- Every value comes from drawing text. Anything worked out (board system voltage, phase from cores/voltage, kW from HP or kVA×PF, a feeder load summed from its circuits, copper assumed) goes in `Candidate.inferred` with a reason and shows in italics. Never infer cable run length. Rows from a "fed from" note alone start unticked.
- Values outside the workbook lists stay as read and show as invalid on the sheet. Reuse `detectColumns`/`toSheetRows`/`cleanValue` for cleaning; do not add independent electrical maths.
- Keep the limits and linear-time parsing (`SCHEMATIC_LIMITS`, `checkImage` before decoding, bounded MTEXT regexes, no `Math.max(...bigArray)`). Each new layout or notation needs a synthetic drawing test in `tests/schematic.test.ts`.
- Images and scanned pages: `src/import/raster.ts` (pure pixel helpers, busbar/feeder tracing) and `src/import/drawing-ocr.ts` (clean image, OCR upright/upward/downward, trace). The OCR engine is injected, so `tests/drawing.test.ts` runs the pipeline with scripted words. Tune against real drawings with a Node harness outside the repo; never commit third-party drawings.

## Local AI reader (user-requested, 2026-11-16)
- Optional "Read with AI" in the schematic review (`src/ui/Schematic.tsx`, `src/import/ai.ts`). It sends the drawing text to a model on the user's own computer only: Ollama (`http://127.0.0.1:11434/v1`) or LM Studio (`:1234`). The user rejected NVIDIA and every hosted model as too leaky for company drawings: never add a remote AI endpoint, API key or proxy. `isLocalUrl` and the page CSP `connect-src` both allow exactly these two local ports; keep them in step.
- The AI only proposes inputs. A value is kept only if its quote is found in the drawing text and the value is in that quote (`aiCandidates`); everything else is dropped and counted. AI values are `inferred` (italic) and go through the same review; the sheet engine still does every calculation. Cable length is never inferred. `tests/ai.test.ts` covers this; keep it passing.
- The user's browser must be allowed by the model server: for Ollama set `OLLAMA_ORIGINS` to the site's origin; for LM Studio enable CORS.
- "Ask AI" on the load list (`src/ui/Assistant.tsx`): the model reads `listBrief` (panel tree, every row with engine results, issues; flagged rows first, capped at `AI_MAX_CHARS`) and answers. It may propose changes (`parseAdvice`): only real rows and input columns, cleaned like an import, never AH (cable runs). Nothing changes until the user ticks and applies; a change is skipped if its row's To moved. Server/model choice is shared (`src/ui/AiPicker.tsx`, localStorage `spool.ai`).

## Load lists grouped by panel (user-requested, 2026-11-16)
- One workbook can hold one load list per MCC/DB panel: a worksheet each (panel-named sheet), or blocks stacked down a sheet under a title row ("DB-L1 fed from MSB-01"). `readPanels` (`src/import/panels.ts`) reads every header block, gives loads their panel as From when blank (italic, with the reason), skips TOTAL rows, keeps a repeated header (page break) on the panel above, and adds the panel feeder from a "fed from" title unticked. Worksheets named in words ("Main LV Switchboard", "Hoist-Gantry Panel", "Shore Power Box") are panels too. Rows with no load name (sub-headings, load-balance summaries, brand catalogues) are skipped and counted, and rows a search/summary sheet repeats from a panel sheet are dropped; identical loads on different panels are kept. Header aliases: "Rated Input Power (kW)" is preferred for G, "Protection Device Rating" for N, "Un" is F. "Load factor" is deliberately not H (diversity): it is operating/rated for the load balance and would undersize a single load's cable. Also (2026-11-17, user-requested): blank phases are worked out from the voltage (380–1000 V three-phase, 220–240 V single-phase, italic); the list's In (A) is checked against the sheet's Ib and loads more than 20% apart are noted; the review lists how every load-list column was read and which inputs the suggestions fill. Load factor, efficiency, C/I/S, consumed kW, starter type and Vital/Essential are not used for sizing. No feeder rows are made for a panel and the load balance (operating factors, design margin) is not recalculated: the user sizes each panel's loads on that panel's tab.
- The load list view has one tab per panel (From) when there are two or more (`listPanel` in `src/ui/state.ts`); Add row on a tab fills its From. Export writes one Cable Sizing sheet per panel (`panelSheets`/`sheetNames` in `src/export/template.ts`): the first panel takes the template sheet, the others are copies (`sheetN.xml`, with copied comment/VML parts, their own filter names, sheet ids in tab order) so formulas, dropdowns and colour rules stay live. A list where a row's To is another listed panel stays on one sheet, because Excel chains total VD within one sheet only. Two or more panels open the review dialog (`SchematicReview workbook`); otherwise the column-mapping import is unchanged. Tests: `tests/panels.test.ts`.

## Hardening (2026-10-30)
- Saved cells hold at most 300 characters (`MAX_CELL`/`clip`); imports, pastes and inputs clip. Numbers follow Excel (`DECIMAL`): `0x1A`, `Infinity` are invalid. Exports never write non-finite cached values or XML-forbidden characters.
- CSV/TSV are limited to 10,000 rows and 200 columns; backups reject damaged JSON with a readable message and drop unknown row keys. `tests/hardening.test.ts` holds the hostile-input cases; add one for any new input.

## Dashboard, calculation panel and report (2026-10-30)
- `src/engine/explain.ts` (size ladder, feeder chain) and `src/engine/issues.ts` (issue list) only re-use `sheet.ts` results and `evaluateRow`. Never add independent electrical maths there or in the UI.
- `src/ui/Calculation.tsx` shows the hand calculation for one row; `src/ui/Report.tsx` is the print-only A3 report (suggested values marked with *). Keep print styles inside `@media print`.
- Undo/redo is whole-project history in `src/ui/state.ts`; pass a cell key to `updateProject` so typing in one cell is one undo step.
- XLSX inputs pass `checkZip` (`src/import/guard.ts`) before ExcelJS. The page CSP blocks inline `<style>`; style through `app.css` or Preact style objects only.

## Visual theme (2026-10-30)
- Colours come only from the tokens at the top of `src/ui/app.css`: light (warm paper `--canvas`, white `--surface`, graphite `--text`, one safety-orange signal `--accent`/`--accent-bright`) and `:root[data-theme=dark]` (graphite). Never add raw hex colours in new rules; use tokens. `@media print` keeps its own fixed light colours.
- Sheet headers use the workbook's own legend tokens (`--xl-input-*` yellow, `--xl-list-*` blue, `--xl-calc-*` grey). Status uses `--ok`/`--bad`/`--warn`/`--info` with `-soft`/`-line` variants; suggestions use `--sug`.
- Primary buttons are graphite (`--primary`); orange is reserved for focus, active tabs, links and highlights. Text tokens meet WCAG 4.5:1 in both themes; re-check contrast if you change them.
- `theme` signal in `state.ts` sets `data-theme` on `<html>`; the choice is stored in localStorage (per browser) and defaults to light.

`src/ui/Drums.tsx` plans drums from runs typed in or taken from a load-list cable group (`loadListGroups` in `src/engine/procurement.ts`). Cable dimensions are always engineer-entered.
