# Public-launch security review

**18 November 2026 · local working tree based on `223d338`.** The app processes project inputs in the browser. The most immediate publication risk was a stale PDF in a previous build directory. That directory is preserved outside the release. The new build copies approved assets, rejects unexpected output files and links, and verifies the blank workbook and bundled libraries before succeeding.

## Scope and evidence

Reviewed the first-party application, importers, calculation and export paths, browser storage, optional AI transport, build scripts, package lock, regression tests and proposed static-host configurations. Claude’s unfinished changes included the host headers, checksum pins and hardening tests. The repository contained no standalone Claude Security findings report. This review uses the OWASP Top 10 as a risk framework. The public hostname, provider account and actual model installations need separate verification. [OWASP Top 10](https://owasp.org/www-project-top-ten/)

## What still needs a launch decision

1. **Resolve or accept the two dependency chains.** ExcelJS uses UUID v4 in its conditional-format writer. The registry advisory concerns v3, v5 and v6 with a caller-supplied buffer. The browser uses ExcelJS’s prebuilt bundle, so overriding a Node dependency alone would leave the browser bundle unchanged. Keep both the browser and workbook round-trip tests when upgrading it. The remaining high-severity picomatch finding is in the development/test tooling. The registry’s latest 4.x release at the time of review was still in the affected range. [UUID advisory](https://github.com/advisories/GHSA-w5hq-g745-h8pq) · [picomatch advisory](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)
2. **Check the actual HTTPS deployment with synthetic data.** Confirm the deployed files match the verified build, including the intended template. Check effective headers, script origins, network traffic during import/OCR/export, and whether the provider adds analytics or error capture. Set the provider’s log retention and describe the actual host and data handling in the public privacy notice.
3. **Verify the supported model setups.** Test the hosted origin with an actual Ollama installation in local-only mode and LM Studio with LM Link off. The browser trusts the service that owns the permitted loopback port. An organisation handling confidential drawings also controls that service’s logging and outbound connections.
4. **Keep import availability in scope.** The file readers enforce size and format limits. XLSX preflight uses the archive’s declared sizes and ExcelJS parses the file in the browser. Actual decompressed memory use is a residual risk when opening untrusted documents. Review parser resource limits before promising support for arbitrary third-party files.
